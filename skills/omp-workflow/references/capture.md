# Capture Before Ship Readiness

## Purpose

Capture converts verified change context into durable project knowledge and ship-ready handoff material.

## Capture steps

1. Summarize the verified change, affected areas, deviations, and evidence.
2. Classify whether the change creates durable project knowledge.
3. Update project documentation when future maintainers need the new fact.
4. Update planning records when the workflow uses durable artifacts.
5. Prepare ship inputs: summary bullets, verification evidence, documentation updates, risks, and waivers.

## Durable project knowledge

Update project documentation when the verified change affects:

- architecture or module boundaries;
- public behavior, commands, configuration, or installation;
- workflow, maintenance practice, or operational procedure;
- resource metadata, registry behavior, or validation rules;
- important decisions that explain why the system works this way;
- troubleshooting, runbooks, or recurring failure modes.

## Writing rule

Project documentation describes the current system. Planning records describe what happened during the workflow.
